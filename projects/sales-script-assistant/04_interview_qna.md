```
Q: 讲讲你这个项目的整体架构？

├── 核心回答: 四层架构——输入识别层（文本/截图/选中文字）→AI推理层（Dify工作流+VLM+LLM）→知识库层（企业话术RAG）→交互层（4大入口）
│   └── 📎 证据: C-ARC-001, PRD-3.1 🟢
├── 🔄 反问: "你们目前的产品架构是分层设计的吗？在什么场景下会遇到多模态输入的需求？"
├── L2 追问: 为什么三种输入方式要统一工作流？
│   ├── 🟢 安全: 当时考虑过分工作流，但维护成本高且无法复用上下文。统一工作流截图先过VLM提取文本，再和文本一起进入LLM，降低维护与迭代成本
│   │   └── 📎 证据: C-ARC-010 🟢
│   └── 🔄 反问: "你们有遇到过多种输入来源需要统一处理的场景吗？"

    │   └── 📎 证据: C-ARC-008, C-FDB-003 🟢
    └── 边界管理: "VLM的具体识别精度需要更多线上数据验证，我设计了评测闭环来持续追踪"
```

## 追问树 2：成本模型与商业价值

```
Q: 单次调用0.0004元是怎么算出来的？
├── 追问意图: 验证数据真实性，考察商业思维
├── 核心回答: 
│   1. 模型选型：千问VL-Flash，输入0.00015元/千T，输出0.0015元/千T
│   2. 实测数据：5张截图→1670输入tokens+50输出tokens=1720T
│   3. 计算：输入1670÷1000×0.00015=0.0002505 + 输出50÷1000×0.0015=0.000075 = 0.0003255
│   4. 向上取整为0.0004元对外口径
│   └── 📎 证据: C-MET-004/008/017 🟡推导
├── 🔄 反问: "你们对AI功能的成本敏感度高吗？一般怎么做成本预算？"
├── L2 追问: 为什么选千问不选GPT-4o-mini？
│   ├── 🟢 安全: 三个维度——①成本：输入单价差6倍(0.00015 vs 0.001) ②延迟：国内节点vs海外节点，输入法要求毫秒级 ③能力：中文聊天截图理解千问更强
│   │   └── 📎 证据: C-MET-017, 项目总览选型表
│   └── 🔄 反问: "你们目前在用哪家的大模型？选型时最看重什么维度？"
├── L2 追问: 月总成本241元怎么构成的？
│   ├── 🟢 安全: API 10.8元 + 服务器约150元 + 其他(存储/CDN/运维)约80元 = 约241元
│   │   └── 📎 证据: C-MET-005/006 🟡
│   └── 🔴 危险: 如果追问"服务器150元是怎么估的"——这部分是PRD给出的估算值，非精确采购单据
│       └── 防线: "150元是基础云服务的估算口径，精确值需要看实际部署后的账单"
└── L3 追问: 规模化到1000坐席成本会怎么变？
    ├── 防线策略: 先承认是预测，再展示预测逻辑——API成本线性增长但固定成本(服务器)摊薄，所以利润率从51.7%升到66.9%
    │   └── 📎 证据: C-MET-007 🟡
    └── 边界管理: "这是基于当前参数的规模化预测，实际还需考虑带宽扩容、并发瓶颈等因素"
```

## 追问树 3：FVR 指标设计

```
Q: FVR这个指标是怎么想到的？
├── 追问意图: 考察数据思维和创新能力
├── 核心回答: 
│   传统满意度问卷存在两个问题：①响应率极低 ②有回忆偏差
│   我发现"刷新"和"复制"这两个行为天然代表了"不满意"和"满意"——用户刷新越多说明推荐越差，复制越多说明越满意
│   所以设计 FVR = min((刷新+1)/(复制+1), 10)
│   └── 📎 证据: C-MET-014/015 🟢
├── 🔄 反问: "你们现在怎么评估AI输出质量的？用的什么指标？"
├── L2 追问: 为什么要加1？直接除不行吗？
│   ├── 🟢 安全: 加1是拉普拉斯平滑，解决三个问题：
│   │   ①复制次数=0时分母为零
│   │   ②区分"0刷新0复制"(=1.0，无互动)和"0刷新1复制"(=0.5，完美推荐)
│   │   ③保证最优值=0.5而非0，语义更清晰
│   └── 📎 证据: C-MET-014 🟢
├── L2 追问: FVR的阈值怎么定的？
│   ├── 🟢 安全: 
│   │   ≤0.5 优秀（首轮即满意）
│   │   0.5-2.0 良好（可优化首轮命中率）
│   │   2.0-5.0 一般（需检查工作流）
│   │   >5.0 较差（需排查模型或Prompt）
│   └── 📎 证据: C-MET-015 🟢
└── L3 追问: FVR上线后的数据表现怎么样？
    ├── 🔴 危险: 产品已上线但FVR数据尚在积累中
    ├── 防线策略: "FVR是我设计并已在PRD中定义的指标体系，目前埋点已上报，数据仍在积累。重要的是评测闭环机制已建立——当数据量足够时，FVR>2.0会自动触发Prompt审查"
    └── 边界管理: "我负责的是指标设计和闭环机制，线上数据的收集和分析需要更长运行周期"
```

## 追问树 4：交互设计与用户体验

```
Q: "零成本嵌入"具体怎么实现的？
├── 追问意图: 验证交互设计能力
├── 核心回答:
│   把AI推荐直接嵌入输入法候选词界面上方。用户打字时，候选词上方自动显示相关话术（最多5条，3字触发），点击即可发送到微信。不需要切换窗口、不需要新开页面
│   └── 📎 证据: C-ARC-003 🟢
├── 🔄 反问: "你们有做过把AI能力嵌入已有产品的尝试吗？用户接受度怎么样？"
├── L2 追问: 为什么不做独立弹窗？
│   ├── 🟢 安全: 独立弹窗需要额外点击才能打开，违背"零成本"原则。嵌入候选词的好处是——用户完全不需要改变操作习惯，打字就是触发，点击就是发送
│   │   └── 📎 证据: 决策复盘表 AI推荐入口 🟡
│   └── 🔄 反问: "你们做这类入口设计时，更倾向轻入口还是重入口？"
├── L2 追问: 选中文字的悬浮气泡为什么要手动选择帮我回/润色？
│   ├── 🟢 安全: 最初设计为自动识别，但发现微信底层不提供区分消息方向的API——选中的文字只是纯文本，无法判断是自己说的还是客户说的。在技术限制下改为手动选择，并通过hover变蓝做视觉引导
│   │   └── 📎 证据: C-ARC-007 🟢
│   └── 边界管理: "这是经典的'理想设计vs技术约束'权衡，好的PM要在约束下找最优解"
└── L3 追问: 覆盖式搜索层是什么设计？为什么这么做？
    ├── 🟢 安全: 关键词输入后弹出新容器覆盖原界面，清空关键词后消失。目的是减少原界面信息干扰，让用户专注搜索
    │   └── 📎 证据: C-UX-003 🟢
    └── 🔄 反问: "你们有类似的'聚焦式'交互设计在产品中吗？"
```

## 追问树 5：VLM与Prompt Engineering

```
Q: 你怎么设计Prompt的？
├── 追问意图: 考察AI PM核心技能
├── 核心回答:
│   Prompt设计服务于话术生成场景，需要结合：

│   ②企业SOP话术库（通过RAG检索匹配）

│   └── 📎 证据: C-ARC-001/010 🟢

├── L2 追问: Prompt效果不好怎么迭代？
│   ├── 🟡 注意: 设计了FVR指标驱动的迭代闭环——FVR>2.0时触发Prompt审查。但目前数据仍在积累
│   └── 边界管理: "闭环机制已建，数据驱动的迭代需要更多线上运行周期"
└── L3 追问: RAG检索的准确率怎么样？
    ├── 🔴 危险: 没有RAG准确率的精确数据
    ├── 防线策略: "RAG检索依赖Dify内置能力，我的重点是元数据标注（company_id/source_id）来确保检索范围精确。准确率的评测在我的方案中通过FVR间接衡量"
    └── 边界管理: "知识库的具体检索算法是Dify平台层的能力，我更关注产品层面的命中率和用户满意度"
```

## 追问树 7：反思与成长

```
Q: 如果重新做这个项目，你会怎么改？
├── 追问意图: 验证反思能力和产品成熟度
├── 核心回答:
│   三点改进：
│   ① 加后端数据库，去掉5轮限制——支持对话持久化和历史上下文复用
│   ② 加结果缓存机制——相同关键词推荐结果缓存24h，预计节省50-70%重复调用（PRD已有方案）
│   ③ 加ABTest框架——让Prompt迭代有对照组，不靠直觉判断效果
│   └── 📎 证据: C-MET-016(缓存预期🟠) + PRD-10.5
├── 🔄 反问: "你们在做AI产品迭代时有用ABTest吗？"
├── L2 追问: 为什么第一版不加后端数据库？
│   ├── 🟢 安全: MVP阶段——先验证核心价值（AI话术生成有用吗？），再补基础设施。5轮限制覆盖95%+的实际场景（客户异议通常2-3轮解决）
│   └── 📎 证据: C-ARC-002 🟢
└── L3 追问: 你觉得这种"先上后优"的策略有什么风险？
    ├── 🟢 安全: 风险在于——如果核心体验不够好，用户第一印象差就不会回来。所以MVP的边界选择很关键：5轮限制不影响核心场景，但如果连基本话术质量都差就不应该上线
    └── 边界管理: "这是经典的MVP取舍——ship fast but ship quality"
```

## 追问树 8：数据与指标深挖

```
Q: 操作路径4+步→1步，4步具体是什么？
├── 追问意图: 验证数据来源，看是否在造数据
├── 核心回答:
│   原流程（4+步）：
│   ①从微信切换到话术库窗口 ②搜索关键词 ③在结果中找到话术并复制 ④切回微信粘贴
│   新流程（1步）：打字时候选词上方自动显示推荐→点击即发送
│   └── 📎 证据: C-MET-010 🟠（流程工程口径，非埋点统计）
├── L2 追问: 回复时间15-30s→3-5s有埋点验证吗？
│   ├── 🟠 防线: "这是动作链估算口径，不是线上埋点均值。产品已上线，埋点数据仍在积累中"
│   └── 防线策略: 主动拆解旧流程时间——"切窗口3-5s + 搜索5-10s + 找到并复制3-5s + 切回粘贴3-5s ≈ 15-25s"
└── L3 追问: 5-7.5人天/月的效率节省怎么算的？
    ├── 🟠 防线:
    │   计算过程：30人 × 12.5min/天 × 22天 ÷ 480min = 约17h ≈ 2人天(保守) 到 6人天(乐观)
    │   区间来源：取决于每人每天调用次数(10-30次)和每次节省时间(15-25s)
    └── 边界管理: "这是假设驱动的估算，我会先把假设条件讲清楚，再给结果"
```
