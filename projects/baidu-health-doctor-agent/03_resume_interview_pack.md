### S - Situation 背景

医美行业市场规模超 3000 亿元 🟡，百度搜索是医美获客的核心公域入口。本项目是快商通的 **首个外部对话类型 API 集成项目** 🟢——快商通作为第三方平台，向百度健康提供外接 AI 医生 Agent 能力，百度负责入口与流量承接（日均 Bot PV 600+ 🟢），快商通负责医生 Agent 能力提供、医生 ID 与机构 Agent 映射维护、对话请求的二次路由。实质是 **达成外部对话类型 API 快速部署与商业化线索变现模式构建**。

**四个核心挑战**：
- **传统落地页留资率仅 3%-5%** 🟡，每个有效线索成本 200-500 元 🟠
- **人工客服年成本约 40-50 万元** 🟠 且无法 7×24 小时在线，约 40% 非工作时段流量流失 🟠
- **头部医生面诊邀约转化率 20%-30%** 🟠，在线客服仅 3%-5%，差距达 4-6 倍
- **三方需求天然冲突**：百度要 CVR、机构要"像真医生"、快商通要低维护成本

**叠加挑战**：百度侧中途更换产品经理 🟢，新 PM 对原始"深聊"需求理解不同，导致产品方向一度不明确。

### A - Action 行动

**行动 1：重新定义对话目标——用漏斗数据推动三方共识**

这其实是**第三版方案** 🎣：第一版按百度"深聊"需求做了 4 个反问/轮，用户嫌太多；第二版减到 2 个，用户在第 3-4 轮仍大量流失。

分析对话日志的漏斗数据后，发现搜索场景的用户耐心非常有限。在 **2025-12-26** 与百度的专项会议上，用数据推动各方达成共识："目标就是留资" 🟢。然后重新设计 5 轮 SOP——每轮只问 1 个精准问题，第 4 轮出诊断小结，第 5 轮引导留资。

**行动 2：解决 P0 级案例卡匹配问题——数据治理 > 算法优化**

排查后发现根因不是检索算法，而是**数据质量**——案例描述太简略（如"双眼皮案例1"），向量检索匹配不准。

三管齐下解决：
1. 制定案例描述**三要素标准**（痛点关键词+手术方案+术后效果）+ 17项审核 Checklist
2. 引入**混合检索** `Score = α×Vector + (1-α)×Keyword`，解决"眼袋/卧蚕"等语义漂移
3. 增加**兜底逻辑**：无高匹配案例绝对不弹，单次对话最多弹 1 次

**行动 3：建立 Bad Case 驱动的持续迭代机制**

每天抽查 10 条对话 🟢，按问题类型分类（幻觉/策略/安全），按频率排序，优先改最高频 Prompt。从 11/17 至 12/01 共进行 **5 轮系统性评测** 🟢（每轮约 20 条 case），问题呈递进式演进：基础质量→体验优化→能力边界→功能稳定→内容安全。

**行动 4：推动工程规范建设**

12/17 生产事故后推动建立独立测试环境，杜绝代码直推生产。推动工作流从"每医生独立"迁移到"按科室统一"（10+独立工作流→2个），维护成本降低约 80% 🟠。

## 二、简历浓缩版

**百度健康医生 IP 智能获客 Agent（外部 API 集成项目）** | 快商通 × 百度健康 | AI PM 实习生 · 主导产品策略（协同研发/运营落地）
2025.11 – 2026.02

**项目背景：** 快商通首个外部对话类型 API 集成项目——快商通作为第三方平台，向百度健康提供外接 AI 医生 Agent 能力（NestJS+Dify+RAG），百度负责入口与流量承接，快商通负责医生 Agent 能力提供、医生 ID 与机构 Agent 映射维护、请求二次路由，达成商业化线索变现模式构建。传统落地页留资率仅 3%-5%，人工客服年成本约 40-50 万且约 40% 非工作时段流量流失，且百度侧中途更换产品经理导致方向一度不明确。

**核心工作：**

- 基于对话漏斗分析推动目标从「深聊」转向「留资」，用数据在百度专项会上推动三方共识；设计 **5 轮多轮对话 SOP**，推动反问策略经历 **三版迭代**（4→2→1 个/轮）
- 制定案例描述 **三要素标准** + **17 项审核 Checklist**，引入 **混合检索 (Hybrid Search)** 策略解决 RAG 语义漂移问题，通过 **Prompt Engineering** 实现 10+ 位医生 IP 个性化；同时引入相似度阈值兜底逻辑（无高匹配绝对不弹）
- 建立 **Bad Case 驱动 Prompt 迭代** 闭环（每日 10 条抽样，分类幻觉/策略/安全），主导 **5 轮系统性评测**（约 100 条 case，问题递进暴露），主导 **6 Case 产品验收** 并协同研发闭环修复
- 主导百度-快商通-机构 **三方协同**，推动工作流架构从独立式迁移到 **按科室统一**（维护成本降约 80%）；推动建立 **独立测试环境**，将医生上线流程标准化为 **8 步 SOP**；独立撰写全套产品文档体系

**核心成果：**

- **10+ 位医生 IP Agent 成功上线**（医美+植发），百度从小流量转入逐步增配
- 案例匹配准确率 约60-70% → **85-90%**，对话完成率提升约 **15-20%**
- AI 替代人工客服 **年省约 80-100 万元**，7×24h 在线
- 新医生上线周期 约5-7天 → **2-3天**，支持标准化复制扩展

## 三、面试讲述脚本（2-3 分钟）

### 🎬 开场（20s）

"我在快商通实习期间，主导了一个和百度健康合作的医生 IP Agent 项目，并和研发、运营协同落地。这个项目挺有意思的——**核心挑战不是让 AI 聊得更像医生，而是让 AI 在 5 轮对话内就完成留资**。" `🎣 钩子 1：反直觉型`

"简单说就是，快商通作为第三方平台，通过标准化 API 向百度健康输出 AI 医生 Agent 能力——百度负责搜索流量入口，我们负责医生 Agent 的能力提供和请求路由，医美机构提供医生资源。最终目标是构建商业化的线索变现模式。"

### ⚡ 挑战（30s）

"这个项目难在哪呢？首先是**三方合作**——百度给流量、我们做 AI、机构提供医生。三方需求经常冲突：百度要留资率，机构要'像真医生'，我们要低成本可扩展。而且百度侧中途换了产品经理，新 PM 对之前的'深聊'需求理解不一样，导致方向一度不明确。"

"其次是技术上的 **RAG 匹配问题**——用户问'黑眼圈'，AI 弹出'面部注射'的案例。百度直接说：**案例卡出错就不能上线**。这是优先级最高的 P0 问题。"

### 🔧 方案（60s）

"我做了四件事。"

"**第一**，重新设计对话策略。**这其实是第三版方案** `🎣 钩子 2：弯路型`——第一版按百度的'深聊'需求做了 4 个反问，用户嫌太多；第二版减到 2 个，还是不行——用户在第 3-4 轮就大量流失了。"

"后来我分析了对话日志的漏斗数据，在 12 月 26 号和百度开的专项会上，用数据推动大家达成共识：目标就是留资。然后重新设计了 5 轮 SOP——每轮只问 1 个精准问题，第 4 轮出诊断小结，第 5 轮引导留资。"

"**第二**，解决案例匹配问题。排查后发现根本不是检索算法的问题，而是**数据质量**——案例描述太简略了，比如就写'双眼皮案例 1'。所以我制定了案例描述三要素标准——痛点关键词、手术方案、术后效果，设计了 17 项审核 Checklist，推动运营重写了所有案例。同时加了兜底逻辑：没有高匹配度的案例宁可不弹，也不推错。"

"**第三**，建立了 Bad Case 驱动的迭代闭环——每天抽 10 条对话标注问题，按频率排序优先迭代。这不是一次性优化，而是**持续跑的机制**。"

"**第四**，推动工程规范。上线第一周就遇到生产事故——开发改了个参数直接推了生产，导致百度接口全挂了 1 个半小时。事故之后我推动建立了独立测试环境。同时把工作流从'每个医生一套'重构为'按科室统一'，10+ 个医生只需维护 2 个工作流。"

### 📊 成果（20s）

"最终 10+ 位医生上线了，覆盖医美和植发两个科室。案例匹配准确率从大概 60-70% 提升到 85-90%。**有个数据比预期好——对话完成率提升了 15-20%** `🎣 钩子 3：意外发现型`，这意味着更多用户走完了全流程。"

"从商业价值看，10 位医生的 AI Agent 相当于替代了 10 名人工客服，年省大概 80-100 万。而且百度的规则是 CVR 越高给越多免费流量，形成了一个正向飞轮。"

"如果面试官追问口径：案例匹配准确率是'正确匹配卡/总弹出卡'，基于 5 轮评测约 100 条 case；对话完成率是'到达第 5 轮人数/进线总人数'；成本节省按 10 位医生的人力替代做 12 个月年化估算。"

### 💡 收获（20s）

"这个项目让我最大的认知转变有两个。第一，AI 产品的核心壁垒不在模型本身，而在于**如何将非结构化的行业知识变成结构化的 AI 知识库**——Garbage In, Garbage Out。第二，**快速迭代不能以牺牲工程规范为代价**——没有测试环境就不要动生产，这是我从生产事故中学到的硬道理。"
